## 23. AI Content Integrity Protocol

Before adding or changing factual content, the AI agent should ask:

### Question 1
Is this information explicitly provided or verified?

If **yes**, it may be used.

If **no**, continue checking.

### Question 2
Is this a harmless stylistic interpretation rather than a factual claim?

If **yes**, it may be written carefully.

If **no**, do not invent it.

### Question 3
Would a visitor reasonably interpret this as a factual claim about Micael?

If **yes** and the information is unverified, do not publish it.

## 26. Content Update Rule

When new information is provided:

1. Verify what the information means.
2. Determine which content area it belongs to.

## 27. Separation of Content and Presentation

Content should be stored separately from UI presentation whenever practical.

For structured content, prefer data sources such as:

```text
data/
├── projects.ts
├── experiences.ts
├── certifications.ts
├── skills.ts
└── social.ts
```

Components should primarily control presentation.

Content files should primarily control factual information.

This makes future updates safer and reduces accidental content changes during design changes.
